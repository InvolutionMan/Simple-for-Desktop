# Simple 网页版

把桌面版 `~/Desktop/test` 里的 SwiftUI 应用 **Simple for Desktop** 升级成现代两栏网页：200px 白色侧栏 + 最大 850px 动态流，白 / 浅灰 / 青绿配色，包含关注 / 广场、图片与视频、评论与楼中楼、真实私信、夜市、语音房麦位、个人主页、信箱。

后端用 Rust（axum），前端是原生 ES Module + CSS，**没有打包步骤**。视觉层在 `web/css/theme.css`（设计变量 + 组件重绘），`app.css` 保留为基础组件。浏览器只拿一个 HttpOnly 会话 Cookie，官方 JWT 留在服务端。

> 第三方客户端，接口来自 `simple.imsummer.cn`。请用自己的账号，遵守官方条款；不要拿它做批量抓取或绕过限流。

## 快速开始

需要 Rust 1.80+（本机 1.96）、macOS 或 Linux。官方 App Key 不写进仓库，运行时从 `.env` 的 `SIMPLE_IM_APP_KEY` 读取。

```bash
cd ~/Desktop/simple-web

./run.sh               # 真实接口：手机号 + 官方短信验证码
./run.sh --mock        # 只看界面：假数据，不发短信
```

打开 <http://127.0.0.1:8787>。

- 真实模式启动时会打印 `[simple] 真实接口：登录时会通过官方短信服务发送验证码`；预览模式侧栏底部会有「离线预览」标识。
- 如果 8787 已经被别的服务占用（比如之前开着的 `--mock`），`run.sh` 会直接报错退出，避免你以为在真实模式里却一直拿到假数据。先 `Ctrl+C` 旧服务，或换端口。
- 第一次编译会把依赖下到项目内的 `.cargo-home/`（本机沙箱只允许写工作区），之后快很多。
- `--mock` 模式下验证码是随机 4 位，打印在启动服务的终端里（5 分钟有效、只能用一次），前端不会自动填；也可以直接访问 `http://127.0.0.1:8787/#/dev` 一键进入。
- 真实模式（不加 `--mock`）走官方短信，验证码不会写进日志或响应。
- 真实私信读取依赖 macOS 官方客户端 `cn.imsummer.simple` 的 plist；Linux 只能使用其余模块。
- 真实登录需要能收短信；同会话 60 秒一条，上游限流时倒计时会延长到 300 秒。

## 视觉与布局

- 两栏：200px 白色侧栏 + 主内容；顶部 60px sticky 导航；动态流最大 850px 居中，不设右侧推荐栏。
- 设计变量集中在 `web/css/theme.css`：主色 `#13B8AD`、背景 `#F7F8FA`、卡片 `#FFFFFF`、正文 `#252525`、次要 `#8A8F98`、分隔 `#EEEEEE`、选中 `#E8F7F5`、危险 `#F05252`。
- 品牌 mark 使用官方 `SimpleMark`：`#1E1D1B` 圆底 + `#FBFAF8` 五根圆角竖条，整体旋转 8°；窄侧栏仍然保留「Simple」和导航文字。
- 动态时间按自然日：当天只显示 `HH:mm`，跨天显示 `M月D日 HH:mm`，跨年补年份；页面每分钟检查一次跨零点。
- 深色模式：首屏内联脚本先套主题避免闪白；侧栏开关位于「设置」按钮上方；首次跟随系统，手动选择后写入 `localStorage` 并全站保持。
- 切换动效：支持 View Transition 的浏览器会从实际点击位置做 560ms 圆形擦除；不支持时退回 380ms 颜色过渡；系统开启「减少动态效果」时直接切换。
- 圆角：按钮 / 输入 8px、动态卡 14px、弹窗 16px；轻阴影；4px 间距体系。
- 消息页：私信 / 频道切换；320px 会话列表 + 聊天详情；搜索、全部已读、只看未读；移动端列表 / 详情切换。环信 `onMessage` 数组会逐条即时处理，活跃私信 / 文字聊天房每 6 秒做一次历史轮询兜底，避免断线时消息滞后。
- 私信详情：时间正序气泡、对方昵称 / 头像、图片消息、文本回复框；打开会话会读取最近 50 条历史。
- 音乐分享卡：标题固定深色，磨砂渐变和封面随鼠标在卡片上的位置轻微移动；开启减少动态效果时关闭。
- 响应式：≥1024 200px 侧栏；768–1023 收窄为 88px，图标下仍显示「Simple」和导航文字；<768 切换为底部 6 项导航，顶栏换行、搜索占整行。

## 架构

```
浏览器 ──同源 fetch──▶ Rust BFF ──Bearer + 官方客户端头──▶ simple.imsummer.cn
   │                     │
   │  HttpOnly sid       └── data/sessions.json（0600）
   └── 拿不到官方 JWT
```

**为什么必须有后端**：

1. 官方接口不带 CORS 头，浏览器直连会被拦；
2. 夜市要求 `appVersionCode: 779` 等客户端标识头，缺了每页只给 4 条；
3. token 不能暴露给浏览器，改由服务端保管；
4. 夜市要翻 10 页聚合、房间要一次并发拉人数 + 麦位，放服务端更省事；
5. 上游错误需要翻成中文，并区分「验证码错」「限流」「登录过期」。

会话流程：登录成功 → 服务端生成随机 sid → `Set-Cookie: simple_sid=…; HttpOnly; SameSite=Lax` → 浏览器后续只带 Cookie。上游返回 401 时删会话并让前端回登录页；网络错误保留会话，避免断网一次就掉登录。

变更类请求会校验 `Origin` 与 `Host` 同源；同源之外的 POST 一律 403。

上游对照：

- 关注 `GET /posts/followings`，广场 `GET /posts`，游标是上一页最后一条的 `id`，每页 10 条；
- 夜市 `GET /night_markets?last_id=&per_page=10`，最多翻 10 页、按 id 去重；
- 房间人数 `GET /chatroom_channels/<id>` 的 `chat_room.chat_room_members_count`（官方「此刻 N 人」同口径）；
- 麦位 `GET /voice_members?channel_id=`，必须有权限，否则上游 500；
- 退房 `DELETE /voice_members?channel_id=&user_id=`，少 `user_id` 会 400。

## 与桌面版的差异

- **私信可文本回复**：服务端从本机官方客户端 plist 读取 `im_id` / `im_password`，换取环信短期 token 后由浏览器 SDK 拉真实会话、历史并发送文本；密码不出服务端，网页只拿到 token。发送成功后才会把气泡加入会话，失败会保留草稿并提示，不伪造成功。账号必须与本机官方客户端一致，否则拒绝读取。
- **麦位依赖权限**：没有权限时上游回 500，网页只显示「这个房间暂时看不到麦位」和人数，不拿聊天室成员冒充。
- **搜索 / 发布**：官方没有公开对应接口，网页版做了本地搜索（已加载内容，按动态 / 用户 / 话题）和发布编辑器；发布只保存浏览器本地草稿，不伪造发帖。
- **发现**：没有对应接口，保留空态与提示。
- **私信页**：只显示官方环信单聊，不再展示系统通知、评论 / 赞通知。会话与历史通过环信 SDK 读取；最后一条可能是自己发的，对方昵称 / 头像会从「对方发来的历史消息」里取，避免显示成自己。自己的头像和昵称会显示在右侧气泡下方，头像与气泡顶对齐。`admin` 单聊显示为「Simple 小助手」。
- **频道中心**：侧栏「频道」只读取当前账号已加入的官方频道，不提供查找 / 加入。频道分区来自官方 `sub_channels`，帖子来自 `posts/channels/all?root_channel_id=`；聊天分类列出官方 `chat_channel` 文字聊天房，并引导到消息页。
- **频道消息**：消息页「频道」分类同时显示账号已加入频道的真实文字聊天房和最新帖子。文字聊天房读取官方 `group.im_id` 对应的环信群聊，支持拉取历史、接收群消息和文本回复；群消息发送使用官方群聊 ID。频道更新只读，点击查看完整帖子。
- **消息媒体**：私信与文字聊天房共用同一套气泡渲染。官方自定义表情（`customEvent: img` + `emoji_id`）读取 `customExts.img`，GIF / WebP 会直接动，并叠加弹入动画；自定义图片可点击放大。语音消息显示时长、播放键和波形，点击播放 / 暂停；文本里的 Unicode 表情也会弹入。语音或图片缺少官方下载地址时显示不可用状态，不伪造播放。
- **个人主页**：动态来自官方 `/api/v3/posts/mine`，不是本地假数据；顶部只显示昵称。发布按钮复用现有编辑器，官方发布接口仍未接入，提交只保存本地草稿。
- **夜市打烊**：`is_open=false` 时仍显示已经开过的房间名称和人数，但房间按钮禁用、不能进入；直接打开 `#/room/<id>` 也会先检查营业状态，不会先显示房间再报「现在不是营业时间」。
- **分享歌曲**：官方 `media.type=music` 会渲染成磨砂渐变附件卡（封面 / 标题 / 歌手 / 外链），用专辑封面做模糊底色，再叠白色半透明渐变；关注和广场都生效。官方有时把歌名、链接、平台拼在 `media.url` 里，卡片会优先取 `music.music_share_url`。
- **更多**：右上角三点菜单是「举报动态 / 对我临时折叠此动态 / 不感兴趣 / 不看Ta发布的动态 / 不让Ta看我发布的动态」。折叠、不感兴趣、不看Ta为浏览器本机行为，不写服务端；举报和隐私设置缺官方接口，会明确提示去官方客户端操作，不伪造成功。
- **视频播放**：官方视频 CDN 会拒绝带 `localhost` Referer 的请求（403）；页面统一 `no-referrer`，实测视频请求无 Referer、返回 206，可正常播放。
- **慢信**：只写入 `localStorage`，不上传。
- **深链进房**：直接打开 `#/room/<id>` 时，标题会先用夜市列表补齐；打烊时显示「夜市已打烊」，不会进入房间。
- **评论里的表情媒体**：只渲染文字内容，`media` / 气泡挂件没做（桌面版也没渲染）。

## 数据库与部署

**不需要数据库。** 我们只是官方接口的转发层：动态、评论、点赞、夜市、麦位和私信都在官方服务器上，本地要持久化的是登录会话（`data/sessions.json`，原子写、0600、30 天过期）；私信凭据不落盘、不进浏览器，只从本机官方客户端 plist 临时读取。

- 单机：一个二进制 + `web/`；`systemd` 守护 + Caddy/Nginx 反代 + HTTPS 即可。
- 多实例：把会话换到 Redis，`session.rs` 是唯一要改的文件；路由不用动。
- 以后有自己的业务数据（收藏、设置、慢信云端版）：SQLite 足够，不必上 Postgres。
- 对外部署前：关掉 `--dev` / `--mock`，Cookie 加 `Secure`，token 落盘加密（`sessions.json` 里是能直接登录的凭据），并给登录接口加一层自己的限流。

默认只监听 `127.0.0.1`；要对外用 `--host 0.0.0.0` 或 `SIMPLE_HOST`。

## 配置

```
./run.sh [--mock|--dev] [--port 8787] [--host 127.0.0.1]
         [--web <目录>] [--data <目录>] [--upstream <URL>]
```

| 参数 / 环境变量 | 默认 | 说明 |
|---|---|---|
| `--port` / `SIMPLE_PORT` | 8787 | 监听端口 |
| `--host` / `SIMPLE_HOST` | 127.0.0.1 | 监听地址 |
| `--web` | `<项目>/web` | 静态目录 |
| `--data` | `<项目>/data` | 会话落盘目录 |
| `--upstream` | `https://simple.imsummer.cn` | 上游地址（调试用） |
| `SIMPLE_OFFICIAL_PLIST` | 官方客户端 plist | 私信凭据路径；不设则用默认的 `~/Library/Containers/cn.imsummer.simple/...` |
| `--dev` | 关 | 开 `/api/dev/session`，用本机已有 token 建会话 |
| `--mock` | 关 | 假数据预览，不访问官方后端 |

`--dev` 的正确用法（本机调试，别对公网开）：

```bash
./run.sh --dev
# 然后从桌面版会话里取 token，只发给本机：
```

## 已知限制

- 语音房只读到麦位表，读不到声网的闭麦状态，所以麦位不画闭麦角标；人数以聊天室成员数为准。
- 房间消息不落库、不互通；关掉页面就没了。
- 夜市列表顺序与人数由官方决定；打烊时会显示房间名，但按钮禁用，不能进入。
- 上游偶发把媒体 URL 拼坏（例如文字和链接粘在一起），前端显示「图片加载失败」占位。
- 搜索只覆盖当前已加载的动态，没有服务端搜索接口。
- 发布按钮复用现有编辑器，但仍只保存本地草稿（`localStorage`），不会真的发到官方服务器；主页动态列表来自官方真实数据。
- 私信必须和本机官方客户端登录同一账号；当前只支持文本回复，图片 / 语音 / 文件发送还没做，也不支持多账号切换读取。
- 私信页只保留单聊，不再显示系统通知、评论 / 回复、收到的赞；这些旧分类已从界面移除。
- 频道列表只记录通过网页进入过的夜市房间；官方客户端加入的频道暂未同步，聊天室历史为空时也只能看到连接后的新消息。
- 频道中心只显示账号已经加入的频道；查找 / 加入暂未实现。网页已读取并展示官方语音房 `voice_channel` 的房间名、成员数等真实信息，但语音播放 / 上麦尚未接入；文字聊天房 `chat_channel` 的消息来自当前账号实际加入的官方群聊，不伪造历史。
- 部分历史语音消息官方接口只返回文件名、时长和 token，没有可播放 URL；网页会显示时长并标为不可用，不伪造播放。
- 私信依赖运行服务这台 Mac 上的官方客户端 plist，只适合单机；远程服务器或多实例要另行处理 IM 凭据，不能把 `/api/im/session` 直接暴露到公网。
- 评论与回复、收到的赞没有官方通知读取接口；私信页不再展示这两类通知，不伪造数据。
- 私信历史只拉最近 50 条；图片消息按官方 URL 展示，语音 / 视频 / 文件暂显示为类型占位。
- 评价、礼物、付费挂件还没做。
